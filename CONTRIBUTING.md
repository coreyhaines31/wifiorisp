# Contributing

Bug reports, ideas, and pull requests are welcome. For anything bigger than a small fix, open an issue first so we can agree on the approach.

## Set up

You need macOS 14 or later, Xcode 16 or later, and [XcodeGen](https://github.com/yonaskolb/XcodeGen). You don't need an Apple Developer account.

```sh
git clone https://github.com/coreyhaines31/wifiorisp.git
cd wifiorisp
brew install xcodegen swiftlint
Scripts/run-local.sh
```

Working with Claude Code or Codex? Point it at this file and at [docs/how-it-works.md](docs/how-it-works.md) first: they explain the layout, the commands, and why the thresholds are what they are.

`run-local.sh` generates the Xcode project, builds it signed "to run locally", and opens the app. Quit any installed copy first: both share the same settings and history.

To work in Xcode instead, run `xcodegen generate` and open `WiFiOrISP.xcodeproj`. The project is generated from `project.yml` and isn't checked in, so edit `project.yml`, not the project. Xcode will ask for a signing team: pick your own, or set Signing to "Sign to Run Locally".

If `xcodebuild` or `swiftlint` complains about the Command Line Tools, point them at Xcode with `sudo xcode-select -s /Applications/Xcode.app`, or prefix commands with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`.

## Test and lint

```sh
cd Packages/WiFiOrISPCore && swift test     # the logic, fast
xcodebuild -project WiFiOrISP.xcodeproj -scheme WiFiOrISP test CODE_SIGNING_ALLOWED=NO   # everything, as CI runs it
swiftlint --strict                          # from the repo root
```

CI runs both on every pull request.

## How the code is laid out

| Path | What's there |
| --- | --- |
| `Packages/WiFiOrISPCore/` | All the logic, with unit tests: sampling, the verdict, events, logging, the ISP report, the speed and lag tests, advice and ceilings, router-maker and provider lookup. No UI. |
| `Packages/WiFiOrISPCore/Sources/wifiorisp-cli/` | A developer CLI (not shipped) that runs the real code from a terminal. |
| `WiFiOrISP/App/` | The menu bar item, the menu card, windows, the welcome window. |
| `WiFiOrISP/Monitor/` | The sampling loop, sleep and wake handling, alerts, Location access. |
| `WiFiOrISP/History/`, `Tests/`, `Settings/` | The History window, the Tests window, Settings. |
| `WiFiOrISP/Appearance/RouterIcon.swift` | The menu bar router and the app icon, drawn in code. |
| `Scripts/` | `run-local.sh`, `release.sh`, the app icon renderer, the router-maker table generator, the Homebrew cask template. |
| `site/` | wifiorisp.com: static HTML, plus the page generator in `site/_build/`. |
| `docs/how-it-works.md` | The measurement method and every threshold. Read this before changing a verdict. |

Put new logic in the package with a test, and keep the app layer thin. Verdict thresholds, poll timing, and ceiling rules all live in the package as named constants.

## The developer CLI

From `Packages/WiFiOrISPCore`:

```sh
swift run wifiorisp-cli samples    # six live samples and the verdict
swift run wifiorisp-cli identify   # router maker, Wi-Fi generation, provider ASN
swift run wifiorisp-cli rpm        # the lag-under-load test
swift run wifiorisp-cli speed      # the M-Lab speed test (results are published by M-Lab)
swift run wifiorisp-cli report     # the last day's ISP report from your log
```

## The website

The pages are static HTML. Most are generated by `site/_build/render.py` from content and researched data in the same folder: `guides.py` (guides and the browser tests), `alternatives.py` (comparisons), `pseo.py` with `isp_data.py`, `router_data.py`, and `router_picks.py` (provider, router login, and router picks pages). The homepage, `index.html`, is written by hand; only its footer links are generated.

```sh
python3 site/_build/render.py      # re-render after any change, and commit both
cd site && python3 -m http.server   # preview at localhost:8000 (add .html to page URLs)
```

The data files are researched from primary sources and every page lists its sources. Values the research couldn't confirm are marked `UNVERIFIED` and never rendered. When providers or routers change, re-run the research and re-render rather than editing pages by hand.

To refresh the router-maker table from the IEEE registry:

```sh
curl -sL https://standards-oui.ieee.org/oui/oui.csv -o /tmp/oui.csv
python3 Scripts/generate-router-makers.py /tmp/oui.csv
```

## Releasing (maintainer)

From an up-to-date `main`, with signing, notarization, and Sparkle credentials set up as described at the top of the script:

```sh
Scripts/release.sh 1.2.0
```

It archives, signs with Developer ID, notarizes the app and the DMG, writes the Sparkle appcast, publishes the GitHub release, and updates the Homebrew cask. The website deploys separately from `main` with `vercel deploy --prod` in `site/`.

## Pull requests

- One change per pull request, with tests for logic changes.
- Run the tests and `swiftlint --strict` before you push.
- Say how you tested it, including on which macOS version, and whether you checked the menu by eye.
- Keep the app private: no analytics, and no new network requests the README's Privacy section doesn't describe.
